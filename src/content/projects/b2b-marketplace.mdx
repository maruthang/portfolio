## Context

A B2B sourcing platform needed an end-to-end marketplace where verified buyers could solicit bids from verified sellers via reverse auction, transact with built-in KYC and dispute resolution, and accept AI-assisted product listings. The existing off-the-shelf marketplace plugins didn't cover reverse auctions, complex seller verification flows, or AWS-Lambda-backed product enrichment.

## My role

I was the full-stack lead, owning the WordPress + Dokan extension layer (17+ custom plugins), the AWS Lambda AI product-creation pipeline, Docker Compose infrastructure, and the GitLab CI/CD pipeline that orchestrates backup → deploy → rollback on every push to main.

## Architecture

- WordPress as the CMS + auth layer; WooCommerce for catalog/cart/checkout; Dokan for multi-vendor.
- Custom plugins layered on Dokan's hooks for reverse auctions, KYC stages, and dispute states.
- AWS Lambda function fronted by API Gateway for AI product enrichment, called from the seller-side admin UI.
- Redis as a session and object cache; MariaDB as primary DB with a nightly logical backup to S3.
- GitLab CI: lint → build Docker images → push to registry → SSH deploy with health-check rollback.

## Key technical decisions

- **Why WordPress + Dokan, not a custom Node app** — Dokan's vendor model and WooCommerce payments gave us marketplace primitives (multi-vendor wallets, payout splits, storefront pages) for free; rebuilding those from scratch would have consumed the entire runway.
- **Why GitLab CI orchestrates backup → deploy → rollback** — on a single-VPS setup, a failed deploy with no prior snapshot can permanently lose customer orders; snapshotting MariaDB and WP uploads before every deploy makes rollback a one-command operation.
- **Why AWS Lambda for AI product creation** — enrichment is a bursty, infrequent workload that can be slow or fail; isolating it as a stateless Lambda means the WordPress request never blocks on it, and we only pay when it runs.

## Constraints

The platform ran on a single VPS with a small team and a hard launch deadline. The off-the-shelf Dokan/WooCommerce plugin ecosystem was designed for standard storefronts, so reverse-auction bidding and multi-step KYC required significant custom plugin work rather than configuration.

## What I'd do differently

I'd extract the AI enrichment Lambda and the reverse-auction logic into proper microservices behind an API gateway from day one. The WordPress monolith couples release cycles I'd rather keep independent — deploying a change to the auction engine today means a full WP deploy with its rollback risk.
