## Context

An employer-sponsored wellness program needed a single mobile app integrating hydration logging, step tracking, and goal management — gated behind the company's existing Keycloak SSO so employees could sign in once and have a unified profile across HR systems. Push notifications for hydration reminders and goal nudges were a core requirement from day one.

## My role

I was a full-stack contributor and led the SSO and push-notification integrations. That covered the NestJS 10 backend, the Ionic 8 + Capacitor 6 + Angular 18 hybrid mobile shell, Keycloak OIDC wiring, Firebase Cloud Messaging setup, and the MySQL data model for wellness logs and goal aggregations.

## Architecture

- Ionic 8 + Capacitor 6 for cross-platform deployment from a single Angular 18 codebase (standalone components throughout).
- NestJS 10 backend with `wellness`, `goals`, and `notifications` modules; tokens validated against Keycloak's JWKS endpoint.
- MySQL as the primary database; a scheduled job aggregates daily step and hydration totals.
- Firebase Cloud Messaging for iOS and Android push delivery (hydration reminders, goal nudges).

## Key technical decisions

- **Why Ionic + Capacitor over React Native** — the in-house team's Angular fluency and the need to embed inside an existing Angular HR ecosystem made this the lower-friction choice; switching frameworks would have added ramp-up time with no offsetting benefit.
- **Why Keycloak SSO over Auth0** — the organisation already ran Keycloak for other products, so identity federation was solved at the org level; reusing it kept access policy in one place and avoided an additional SaaS dependency.
- **Why Firebase Cloud Messaging, not a custom push service** — FCM handles iOS and Android delivery, retries, and topic subscriptions out of the box at zero per-message cost, which is the right tradeoff for a wellness app where notification volume is predictable and low.

## Constraints

The hybrid Ionic + Capacitor stack trades some native UX ceiling for a single-codebase advantage, which the project accepted given the team skill mix. Corporate IT mandated Keycloak for auth and had telemetry policies that shaped what data the app could collect and where it could be stored.

## What I'd do differently

I'd push the step-count and hydration write logic into an async worker so the request path doesn't block on database health for what is essentially append-only telemetry. An offline-first cache for hydration logs would also prevent data loss when users are on intermittent connections.
