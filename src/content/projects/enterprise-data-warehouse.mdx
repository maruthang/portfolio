## Context

Executive leadership at an insurance carrier needed unified, reliably-fresh KPIs across policies, claims, and channels. Source data lives in heterogeneous systems with inconsistent schemas, sporadic delivery, and audit requirements that demand traceability from dashboard back to source row.

## My role

I'm a data engineering contributor, building the Silver and Gold layer transforms and the dbt-style modelling that feeds Power BI. That includes writing idempotent PySpark merges for Silver, dbt models and data-quality assertions for Gold, and wiring Databricks Asset Bundles so every job and schedule is checked-in code.

## Architecture

- ADLS Gen2 as lake storage; Delta tables at every layer (Bronze, Silver, Gold).
- Bronze ingested via Auto Loader for streaming files and Databricks Jobs for batch; raw data lands untransformed.
- Silver transformations in PySpark, with idempotent merges keyed on natural keys and SCD Type 1/2 patterns for slowly-changing dimensions.
- Gold layer via dbt with the Spark adapter; tested with `not_null`, `unique`, and freshness assertions.
- Databricks Asset Bundles for IaC; Dynatrace monitors job-level SLAs; Delta `OPTIMIZE` + `VACUUM` + `Z-ORDER` keep query latencies predictable.

## Key technical decisions

- **Why Medallion (Bronze / Silver / Gold) over flat staging** — explicit layer contracts make data-quality regressions diagnosable; when a dashboard metric drifts, I can rerun a single layer rather than triggering a full re-ingest from source.
- **Why SCD Type 2 over Type 1 for slowly changing dimensions** — insurance reporting needs historical truth (a policy's prior premium, prior coverage); Type 2 preserves the timeline for dashboard slicers, whereas Type 1 would silently erase it.
- **Why Databricks Asset Bundles for IaC over notebook-mode** — every job, schedule, and cluster definition becomes reviewable code; it replicates a workspace cleanly into staging without click-through, and CI can validate bundle syntax before promotion.

## Constraints

This is a learning project, so some design decisions are exploratory rather than driven by production SLAs. Insurance-domain compliance shapes data retention rules and access controls. Power BI consumers expect specific table shapes in Gold, which constrains how freely the dbt models can be refactored.

## What I'd do differently

I'd wire Delta's change-data-feed into downstream Silver transforms so re-runs only touch changed partitions instead of full-table merges. That would cut both compute cost and the re-run blast radius when an upstream schema changes.
